# Editorial Style Wiki

## What works (keep doing)
- Keep the headline, intro, and body aligned on one confirmed development; consistency across the piece is a strength.
- A small, concrete update can stand on its own when the fact pattern is clean and clearly stated.
- Tight factual discipline is a virtue: stay inside the available source material from start to finish.
- Direct, specific writing with no unsupported embellishment remains a strong default.
- Avoiding source-meta language helps the update read as a clean story, not a process note.
- Use a restrained, fact-first lede when the item is narrow and does not need larger framing.
- Preserve a clear line from headline to body so the reader immediately understands the core update.
- A concise status note can still be publishable if it answers one concrete question well.
- [columnist] Keep a narrow update grounded in the named fact; don’t force a bigger narrative when the source is modest.
- [insider] Plainly state the readiness/availability fact without layering in extra speculation.

## What to avoid
- Don’t widen a small status update into roster-picture or camp-role speculation that the source does not support.
- Don’t pad a thin fact with generic “why it matters” language if the digest does not supply it.
- Don’t repeat the headline verbatim in the subhead or intro; avoid redundant phrasing.
- Don’t let filler language create facts the source never supplied.
- Don’t overstate certainty or imply consequences the source does not verify.
- Don’t bury the strongest factual takeaway under broad summary language.
- Don’t force a broader frame when the real story is a single confirmed development.
- Don’t present a source bundle with uneven fit as if it were fully clean; keep the structure disciplined.
- [columnist] Don’t turn a narrow readiness note into team-level implications unless the source directly supports that leap.
- [insider] Don’t add unsupported specifics beyond the confirmed readiness fact; keep the lede simple and factual.
- [analyst] Don’t fabricate context or player details when the source digest is thin; grounding must come from the source, not the template.
- Source-side, not fixable in prose: if the digest is effectively empty, there is no factual base to validate or improve the piece; the only safe move is to avoid unsupported roster-context framing.
